# Runtime Radar

### Найдите причину замедления Node.js — без отправки телеметрии в облако.

Runtime Radar — локальный инструмент наблюдения за работающим Node.js-приложением. Он собирает показатели процесса, запросы, логи и ошибки, а затем показывает их на понятной панели. Данные и база остаются на вашем компьютере.

> **Для кого:** разработчики Node.js и небольшие команды, которым нужно разобраться, почему API тормозит, растёт память или появляются ошибки.

**Интерфейс:** русский и казахский · **Хранилище:** SQLite на устройстве · **Лицензия:** MIT

## Что можно увидеть

- **Нагрузка процесса:** CPU, RSS/heap-память и задержка цикла событий Node.js.
- **HTTP-запросы:** маршрут, код ответа и длительность, включая P95 — показатель задержки, быстрее которого укладываются 95% запросов.
- **Ошибки и аномалии:** хронология ошибок, ответов 5xx, роста памяти и повторяющихся задержек.
- **Сравнение запусков:** сравните медианные показатели текущей сессии с предыдущей.
- **Отпечаток среды:** версия Node.js и приложения, ОС, архитектура и PID — без сбора произвольных переменных окружения.
- **Отчёты:** экспорт выбранной сессии в JSON или Markdown.

Это инструмент диагностики подключённых Node.js-приложений, а не монитор всего компьютера и не замена полноценной системе продакшен-алёртов. Без подключённого агента панель не получает данные.

## Быстрый старт

Нужны **Node.js 22+** и **npm 10+**.

```powershell
npm ci
npm run build
npm run dev
```

Откройте <http://127.0.0.1:4318>. При первом запуске ядро создаст локальный токен в `.runtime-radar/token` и выведет его в терминал. Не публикуйте этот токен.

Чтобы сразу увидеть данные, запустите пример в **новом окне PowerShell** из папки проекта:

```powershell
$env:RUNTIME_RADAR_TOKEN = (Get-Content .runtime-radar\token -Raw).Trim()
npm run demo
```

Оставьте демо запущенным. В ещё одном окне PowerShell создайте тестовую нагрузку:

```powershell
Invoke-RestMethod http://127.0.0.1:4320/health
Invoke-RestMethod http://127.0.0.1:4320/slow
Invoke-RestMethod http://127.0.0.1:4320/busy?ms=500
Invoke-RestMethod http://127.0.0.1:4320/memory?mb=8
```

Вернитесь в панель: там появятся сессия, метрики и запросы. Маршрут `/fail` специально возвращает HTTP 500 для проверки отображения ошибок:

```powershell
Invoke-RestMethod http://127.0.0.1:4320/fail
```

Для работы без Vite сначала выполните `npm run build`, затем `npm run start`; собранная панель будет доступна на <http://127.0.0.1:4318>.

## Подключение собственного приложения

Установите или подключите пакет `@runtime-radar/agent`, задайте токен из локального ядра и запустите агент при старте приложения. Для Express:

```ts
import express from "express";
import { httpMiddleware, startAgent } from "@runtime-radar/agent";

const app = express();
const radar = startAgent({
  appName: "orders-api",
  appVersion: process.env.APP_VERSION ?? "local"
});

app.use(httpMiddleware(radar));

app.get("/orders/:id", async (request, response) => {
  response.json({ id: request.params.id });
});

app.listen(3000);
```

Задайте `RUNTIME_RADAR_TOKEN` — агент по умолчанию подключается к `ws://127.0.0.1:4318/agent` и отправляет образцы раз в секунду. При необходимости укажите `RUNTIME_RADAR_URL`, `RUNTIME_RADAR_INTERVAL_MS`, `RUNTIME_RADAR_APP_NAME` или `RUNTIME_RADAR_APP_VERSION`. Для обработанных ошибок можно вызвать `radar.captureError(error, { operation: "checkout" })`.

## Приватность и ограничения

- Ядро принимает соединения только на `127.0.0.1`; API защищено токеном.
- HTTP-наблюдение сохраняет метод, шаблон маршрута, статус и длительность. Исходный URL, query-параметры, заголовки и тела запросов/ответов не собираются.
- Перехват консоли включён по умолчанию: распространённые секреты и bearer-токены маскируются. Его можно отключить через `startAgent({ captureConsole: false })`; проверяйте содержимое логов своего приложения.
- SQLite и токен находятся в `.runtime-radar/` и исключены из Git. История ограничена 100 000 событий и 200 сессиями; буфер агента — 250 событий.
- CPU показан относительно одного логического ядра, поэтому значение может превышать 100%. Задержка event loop — среднее за интервал, а не максимум.
- События на временной шкале показывают близость по времени, но не доказывают причинно-следственную связь. Сравнение запусков — ориентир по медианам на одной машине, а не контролируемый бенчмарк.
- Не выставляйте локальный порт в публичную сеть или reverse proxy.

```powershell
npm test

```

В GitHub Actions выполняются сборка и тесты на Node.js 22.

### Структура проекта

| Папка | Назначение |
| --- | --- |
| `packages/shared` | Форматы событий, проверка данных, пороги и маскирование секретов |
| `packages/agent` | Метрики Node.js, HTTP middleware, сбор логов и транспорт |
| `packages/core` | Локальный API/WebSocket, SQLite и правила аномалий |
| `apps/dashboard` | Панель мониторинга на React и Vite |
| `examples/demo` | Демоприложение с маршрутами для проверки разных сигналов |
